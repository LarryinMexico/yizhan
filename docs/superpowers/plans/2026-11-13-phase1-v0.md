# Yizhan Phase 1 (v0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A publicly reachable webhook delivery service where an event sent to the API is delivered, retried, signed, and recorded, by **2026-12-10**.

**Architecture:** A FastAPI service writes messages and deliveries to PostgreSQL and publishes one Kafka record per delivery. A worker consumes records, sends signed HTTP requests, and records each attempt. A scheduler re-publishes deliveries whose retry time has passed. Everything runs under Docker Compose on one AWS EC2 instance behind Caddy.

**Tech Stack:** Python 3.13, uv, ruff, pytest, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, aiokafka, httpx, redis-py, Testcontainers, Docker Compose, Caddy, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-12-webhook-delivery-platform-design.md`
**Contracts (normative):** `docs/design/contracts.md`
**Testing standard:** `docs/testing.md`
**Learning guide:** `docs/learning/phase1-guide.md`

## Global Constraints

- `docs/design/contracts.md` is normative for schemas, routes, record formats, and algorithms. This plan does not repeat them; each task names the sections it implements. Implementation code is deliberately not written out here: the contracts and the listed tests define the behaviour.
- **`src/yizhan/delivery/backoff.py` and `src/yizhan/delivery/worker.py` are written by the owner by hand.** A model must never write or complete their implementations. See `CLAUDE.md` for the hint rules.
- All commands go through `uv run`. Never bare `pytest`, `ruff`, or `python`.
- No mocks for PostgreSQL, Kafka, or Redis.
- Pin dependency versions through `uv.lock`. Pin Docker image tags to an exact version; before pinning, confirm the current stable tag and required environment variables on the image's official page (the values in this plan were not verified against official sources).
- Stage files by explicit path. Check `git status -sb` and `git diff --cached --name-only` before every commit.
- Never commit `.env`. Refer to secrets by variable name only.
- Each milestone begins with the owner reading its section of the learning guide and ends with the owner writing its ADRs and answering its self-check questions.
- Scope is fixed. Not in phase 1: transactional outbox, Kubernetes, metrics, Release Radar, React dashboard. New ideas go to `docs/backlog.md`.
